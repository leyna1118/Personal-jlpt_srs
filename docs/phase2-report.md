# Phase 2 完成報告:核心複習引擎

## 做了什麼

寫了 `index.html` + `css/style.css` + `js/app.js`,實作了整套複習機制:

- **不斷連續抽卡**:優先順序是「答錯留著要重考的字」>「到期複習的字」>「新字(有每日安全上限,預設30,可調)」。
- **新字第一次出現**是介紹卡(完整顯示漢字、讀音、意思、例句),只有「已經認識(不計入今日額度)」跟「沒看過,開始學」兩個按鈕。
- **第二次以後**全部是隨機測驗題型,四種:看讀音選意思(不顯示漢字)、看意思選單字(選項只顯示平假名)、看漢字打讀音(需一字不差)、例句克漏字(例句挖空選正確單字),每次重考隨機換題型。
- **幹擾選項**:選意思模式優先抓近義詞;選單字模式優先抓讀音相似的字;兩種模式都會故意把自動詞/他動詞配對字混進去考你;都有「顯示漢字」提示按鈕可以自己選按。
- 答對離開重考佇列、進入正常SRS排程;答錯顯示正解、留著之後在同一次複習中重考。
- 「這個字我完全會了,不用再出現」按鈕隨時可按,單字管理頁可以恢復。
- 單字管理頁:9個分類(N1-3 × 高中低頻)分別顯示「已完全會/還沒背好」數量,可搜尋篩選。
- 設定頁:勾選學習範圍(9個分類)、調整每日新字上限、匯出/匯入進度、重設。
- 進度自動存在瀏覽器 localStorage,關掉分頁/重開機都還在。
- 男友(黑尾/研磨)先接了基本的觸發點(打開網站、答對答錯、標記完全會、連續答對里程碑),機率黑尾40%/研磨40%/兩人一起20%,台詞先放了每種情境各1-2句當範例,**完整的台詞庫還沒寫,這是下一階段(男友對話系統)要做的事**。

## 測試

用 Playwright 寫了自動化測試,實際跑過整個流程,不是憑感覺說做完了:

- 連續抽卡200+次,四種測驗題型都有實際觸發並驗證顯示正確(包含克漏字有正確挖空、選單字模式預設只顯示平假名、顯示漢字按鈕能正常運作)。
- 驗證自動詞/他動詞配對邏輯:只要配對雙方都在你目前選的學習範圍內,**100%緊鄰出現**;範圍外的字(例如你沒勾N1,但配對字是N1)不會硬湊在一起,這是合理的。
- 驗證SRS到期複習優先權(手動塞一個到期的字,確認重開頁面後優先被抽到)。
- 驗證進度存在localStorage、重開頁面資料還在。
- 驗證每日新字上限設成0之後不會再跳新字介紹卡。
- 驗證匯出/匯入進度檔案可以正確還原。
- 全程沒有任何JavaScript錯誤。
